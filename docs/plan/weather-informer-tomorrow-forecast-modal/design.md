# Дизайн-документ: Детальный прогноз на завтра (Всплывающее окно)

## 1. Замысел и мотивация
Планшетный погодный информер работает в круглосуточном режиме настенных часов. По умолчанию правый блок `#forecast` отображает крупный шрифт с двумя ближайшими скользящими периодами суток, чтобы показатели читались с расстояния 2–3 метров. 
Однако при планировании следующего дня пользователю требуется детальная картина на все сутки (ночь, утро, день, вечер) с ключевыми метеопараметрами: температура (с ощущаемой), осадки, влажность, ветер и барометрическое давление (с индикацией изменения).
Цель доработки — реализовать удобный сенсорный сценарий: тап по блоку прогноза открывает аккуратное модальное окно с прогнозом на завтра, а через 40 секунд бездействия (или по повторному тапу / кнопке закрытия) экран автоматически возвращается к часам.

---

## 2. Goals, Non-goals, Anti-goals

### Goals
- Интерактивный тап по блоку прогноза (`#forecast`), открывающий оверлей прогноза на завтра `#modal_tomorrow_forecast`.
- Заголовок с точной датой и днем недели: например, `«Прогноз на завтра: Понедельник, 16 ноября»`.
- 4 наглядные колонки частей суток в ряд: **Ночь | Утро | День | Вечер**.
- В каждой колонке отображаются 5 обязательных параметров:
  1. **Температура**: диапазон мин/макс (`0°..+2°`) и ощущаемая температура (`ощущ. -3°`).
  2. **Погода и осадки**: погодная иконка, статус («пасмурно», «дождь», «снег»), вероятность осадков (при наличии в данных) и интенсивность.
  3. **Влажность**: процент влажности (с иконкой капли `💧`).
  4. **Ветер**: стрелка направления ветра (с точным градусом поворота), скорость в м/с и порывы при наличии.
  5. **Давление**: значение в мм рт. ст. и индикатор тренда/динамики (`↗`, `↘`, `→`) относительно текущего фактического давления или соседних периодов.
- Нижний информационный блок: время восхода, заката и долгота светового дня на завтра.
- Механизмы закрытия:
  - Кнопка закрытия `✕` в правом верхнем углу (крупный tap target ≥44px для пальца).
  - Тап по полупрозрачной подложке вне карточки.
  - Нажатие клавиши `Escape`.
  - Автоматическое закрытие по таймеру через 40 секунд неактивности.
- Полная адаптивность: чистое отображение без наложений и обрезаний на разрешениях 1024×600 (Alldocube/BQ) и 1280×800.
- Строгая совместимость с Android WebView 6.0/7.0 (100% ES5 синтаксис).

### Non-goals
- Многодневный прогноз на неделю (3–7 дней) в этом окне не выводится (провайдеры в бесплатном режиме гарантируют надежные сутки).
- Почасовой 24-часовой график в рамках Подхода 1 опущен в пользу читаемости и лаконичности 4 частей суток.

### Anti-goals
- Не оставлять модальное окно открытым бесконечно: информер на стене не должен "зависнуть" в режиме прогноза.
- Не использовать тяжелые внешние UI-фреймворки (Bootstrap, React и т.д.): чистый CSS flexbox/grid + нативный Vanilla JS/jQuery.
- Не ломать существующие UI-тесты и верстку основного экрана.

## 3. Ограничения и зависимости
- **Стек**: Vanilla JS / jQuery (100% ES5), CSS3 flexbox, HTML5.
- **Окружение**: Android 6.0 / 7.0 WebView (Chrome 53+), современные браузеры.
- **Источник данных**: массив `data.forecasts[1]` из `weather.json`, содержащий поля `parts.night`, `parts.morning`, `parts.day`, `parts.evening`, а также `hours`, `sunrise`, `sunset`.

### 4.2. Карточка части суток (`.mtf_card`)
Каждая из 4 колонок содержит:
1. Заголовок периода: `«Ночь»`, `«Утро»`, `«День»`, `«Вечер»` + временной интервал (00:00–06:00, 06:00–12:00, 12:00–18:00, 18:00–24:00).
2. Иконка погоды + текстовое описание (пасмурно, ясно и т.д.).
3. Температура: крупная основная (диапазон `min..max` или `avg`) + компактно «ощущ. -3°».
4. Метрики (аккуратный список с иконками):
   - Осадки: `0 мм` / `без осадков` (или вероятность `%`).
   - Ветер: стрелочка `↑` с поворотом `transform: rotate(N deg)`, `3.4 м/с`, порывы `до 6.2`.
   - Влажность: `💧 79%`.
   - Давление: `752 мм` и динамика относительно факта (`↗ +3 мм` / `↘ -2 мм` / `→ 0 мм`).

## 5. Принятые решения

### 5.1. Решения пользователя
- Выбран **Подход 1**: компактная 4-периодная карточка на завтра без перегруженных графиков.
- Обязательный состав метрик: **температура**, **осадки**, **влажность**, **ветер**, **давление (с динамикой изменений)**.
- Интерактивный триггер: тап/клик по блоку прогноза (`#forecast`).

### 5.2. Решения инженера (Builder calls)
1. **Расчет динамики давления**:
   - Сравнивается давление периода завтрашнего дня с текущим фактическим давлением (`data.fact.pressure_mm`).
   - При разнице $\ge +1$ мм рт. ст. отображается зелёный бейдж `↗ +X`.
   - При разнице $\le -1$ мм рт. ст. отображается синий/красный бейдж `↘ -X`.
   - При разнице $< 1$ мм рт. ст. отображается нейтральный бейдж `→ без изм.`.
   - Если провайдер не отдает давление в частях суток (например, Open-Meteo), значение агрегируется по часам `hours` соответствующего диапазона (0–5, 6–11, 12–17, 18–23).
2. **Таймаут автозакрытия**: 40 секунд с визуальным счетчиком/индикатором или беззвучным сбросом при повторном касании. Любое касание внутри окна продлевает таймер еще на 40 секунд.
3. **Хинт на основном экране**: при наведении курсора на блок `#forecast` (на ПК) курсор меняется на `pointer`, а на экранах планшетов добавляется еле заметная подсказка/иконка лупы/интерактивности, не портящая чистый вид настенных часов.
4. **Случай отсутствия данных на завтра**: если `forecasts[1]` по какой-то причине отсутствует (например, усеченный ответ API), карточка отображает информационное сообщение `«Прогноз на завтра обновляется...»` с возможностью принудительного обновления.

   - Клик по бэкдропу -> окно закрывается.
   - Срабатывание автозакрытия через таймаут.
