# Исследование (Research): Локальный веб-сервер на планшете, простое развёртывание без ADB и интеграция официального Gismeteo API

## 1. Введение и цели

Пользователь поставил три взаимосвязанные задачи для проекта `Weather Informer`:
1. **Веб-сервер прямо на планшете**:
   - Поднятие легковесного HTTP-сервера на самом Android-устройстве.
   - Веб-интерфейс для управления всеми настройками (`config.json`, координаты, ключи, источники, поворот экрана).
   - Отображение самого информера (`http://127.0.0.1:8080/` вместо `file:///sdcard/Download/informer.html`), устраняющее проблемы CORS и изоляции `file://`.
   - Возможность загрузки файлов на планшет (обновление `informer.html`, скриптов, стилей) через веб-интерфейс с любого устройства в сети (с телефона/ПК).
2. **Упрощение развёртывания на планшет**:
   - Анализ методов быстрой установки/настройки, в идеале без подключения по ADB и без проводов (например, прямо с соседнего смартфона).
3. **Поддержка официального ключа Gismeteo**:
   - У пользователя появился API-ключ Gismeteo с ограниченной квотой.
   - Реализация аналогично Яндекс.Погоде: кэширование на сервере с защитой квоты, раздача по локальной сети (`/weather.json`, `/api/weather/gismeteo`) и поддержка прямого подключения с клиента.

## 2. Анализ компонента 1: Веб-сервер на планшете

### 2.1. Проблемы текущей схемы (`file:///sdcard/Download/informer.html`)
- **CORS и безопасность WebView**: браузерный движок Android блокирует AJAX-запросы и чтение соседних файлов (`config.json`, `jquery.min.js`) из `file://`. Требуется патчить скрытые флаги `allow_universal_access_from_file_urls` в `/data/data/.../shared_prefs/` с правами root.
- **LocalStorage и изоляция origin**: `file://` не имеет валидного origin, что приводит к стиранию или сбоям `localStorage` при некоторых перезапусках WebView.
- **Сложность обновления**: любая правка требует `adb push` или физического подключения кабеля.

### 2.2. Требования к серверу на планшете
1. **Порт**: стандартный непривилегированный (например, `8080` или `8085`).
2. **Статика**: отдача `informer.html`, `jquery.min.js`, стилей, иконок.
3. **Веб-настройки (`/settings`, `/api/settings`)**:
   - Удобная мобильная страница с полями:
     - Координаты (`lat`, `lon`), кнопка «Определить по GPS/IP».
     - Выбор основного источника: `Yandex`, `Gismeteo`, `Open-Meteo`, `Foreca`, etc.
     - Ввод ключей: Яндекс API, Gismeteo Token, Foreca Bearer, OpenWeatherMap.
     - Адрес кэширующего сервера (`server_url`) или режим прямого доступа.
     - Настройки дисплея: ориентация (`ROTATION_0`, `90`, `180`, `270`), скрытие системных панелей.
   - Сохранение в `config.json` на планшете и отправка сигнала/события на перезагрузку информера.
4. **Файловый менеджер / Загрузка (`/upload`, `/api/upload`)**:
   - HTML-форма с drag-and-drop для загрузки файлов на устройство (`informer.html`, фоновые изображения, звуки).
   - Кнопка «Стянуть обновление с домашнего сервера» (one-click sync).
5. **Трансляция в киоске**:
   - Киоск открывает `http://127.0.0.1:8080/`. Так как источник `http://`, CORS между локальными файлами исчезает, а запросы к локальному серверу или внешним API работают в штатном контексте Web.

### 2.3. Варианты реализации веб-сервера на Android
- **Вариант А: Самодостаточное Android-приложение «Informer Kiosk & Server» (Рекомендуется)**:
  - Единый APK, совмещающий встроенный микро-HTTP сервер (на базе NanoHTTPD или стандартного Java `HttpServer`) и полноэкранный `WebView`.
  - Преимущества:
    - 1 клик на установку. Никаких сторонних программ не нужно.
    - Не нужен Root.
    - Автозапуск при включении устройства (`RECEIVE_BOOT_COMPLETED`).
    - Удержание экрана включенным (`FLAG_KEEP_SCREEN_ON`).
    - Скрытие status bar и navigation bar прямо из кода Activity (`SYSTEM_UI_FLAG_IMMERSIVE_STICKY`).
- **Вариант Б: Легковесный фоновый сервер-компаньон (APK) + существующий WebView Kiosk**:
  - Маленький APK сервиса, поднимающий сервер на 8080. WebView Kiosk направляется на `http://127.0.0.1:8080/`.
- **Вариант В: Локальный веб-сервер внутри самого WebView Kiosk (если поддерживается)**:
  - WebView Kiosk не имеет встроенного веб-сервера с загрузкой файлов.

## 3. Анализ компонента 2: Простое развёртывание без ADB (со смартфона)

### 3.1. Существующий барьер
Сейчас для настройки планшета требуются:
1. Компьютер с Linux и установленным Android SDK Platform-Tools.
2. Включение отладки по USB/Wi-Fi на планшете.
3. Доступ по `su` (root) для инъекции конфигурации в каталог `/data/data/uk.nktnet.webviewkiosk`.
4. Запуск bash-скриптов `informer-to-tablet.sh` и `setup-kiosk.sh`.

### 3.3. Рекомендованная стратегия развёртывания
1. Собрать единый чистый APK информера:
   - Включает встроенные статические ресурсы (`informer.html`, скрипты, шрифты) прямо в `assets/`, так что информер работает **сразу из коробки** даже без интернета.
   - Включает встроенный HTTP-сервер на порту `8080` (с веб-мордой настроек и загрузчиком файлов).
   - Полноэкранный Kiosk WebView, запрещающий засыпание экрана и скрывающий системные бары.
2. В `caching_server.py` добавить страницу `/install` с QR-кодом для моментальной загрузки APK на планшет в домашней сети WiFi.

## 4. Анализ компонента 3: Интеграция официального API Gismeteo

### 4.1. Архитектура официального API Gismeteo
- **Базовый URL**: `https://api.gismeteo.net/v2/`
- **Аутентификация**: заголовок запроса `X-Gismeteo-Token: <ваш_токен>`
- **Эндпоинты**:
  - `GET /v2/search/cities/?latitude={lat}&longitude={lon}&limit=1` — поиск ID города по координатам.
  - `GET /v2/weather/current/?latitude={lat}&longitude={lon}` (или `{city_id}`) — текущая погода.
  - `GET /v2/weather/forecast/aggregate/?latitude={lat}&longitude={lon}&days=3` (или `/v2/weather/forecast/?...`) — детальный прогноз по часам и периодам.
- **Особенности квоты**:
  - Официальные ключи обычно имеют суточный лимит запросов (например, 50, 100 или 500 запросов/день).
  - Требуется строгое кэширование на сервере (интервал 30–60 минут, дающий ~24–48 запросов в сутки).
  - В случае ошибки 401/403/429 — пауза и автоматический fallback (на текущий inform-service Gismeteo без токена или Open-Meteo).

### 4.2. Схема «Раздача с сервера + прямое подключение» (как с Яндексом)
1. **На кэширующем сервере (`caching_server.py`)**:
   - В `config.json` добавляются параметры:
     - `gismeteo_api_key`: ключ доступа.
     - `primary_source`: выбор источника по умолчанию (`yandex` или `gismeteo`).
   - Модуль `gismeteo_provider.py` расширяется поддержкой официального API:
     - Если задан `api_key`, запросы идут к `https://api.gismeteo.net/v2/` с заголовком `X-Gismeteo-Token`.
     - Если ключ не задан или исчерпан лимит, провайдер бесшовно использует внутренний `inform-service` (XML) как надежный fallback.
   - Кэширование сохраняет результат в базу/файл со `src: "Gismeteo"`.
   - Эндпоинты: `/weather.json` (основной) и `/api/weather/gismeteo` (целевой запрос источника).
2. **В веб-интерфейсе информера (`informer.html`)**:
   - Добавление опции `gismeteo_api_key` в настройки.
   - Поддержка прямого вызова API Gismeteo:
     - При прямом подключении клиент запрашивает API Gismeteo.
     - Поскольку браузер может натолкнуться на CORS (если API Gismeteo не отдает `Access-Control-Allow-Origin: *`), при работе через веб-сервер планшета запрос проксируется через встроенный локальный сервер планшета (`http://127.0.0.1:8080/proxy/gismeteo`), полностью снимая ограничения CORS!
   - Конвертер ответа Gismeteo v2 JSON в стандартный формат погодного информера (температура, влажность, давление в мм рт. ст., ветер, иконки, астрономические данные).

## 5. Выводы исследования

1. Реализация веб-сервера на планшете решает корневую проблему проекта: избавляет от `file://`, проблем с безопасностью WebView и необходимости рутовать планшеты ради правок XML.
2. Для ультра-простого развёртывания со смартфона идеальным решением является подготовка специализированного открытого Android-приложения (`Informer Kiosk & Server`) с раздачей по QR-коду прямо из `caching_server.py`.
3. Поддержка ключа Gismeteo гармонично встраивается в текущую архитектуру: кэширующий сервер защищает квоту токена, а при недоступности сервера планшет может обращаться к Gismeteo напрямую через свой локальный сервер-прокси.
